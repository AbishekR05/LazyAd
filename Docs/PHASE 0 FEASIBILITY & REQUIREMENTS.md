## 1. Executive Summary

**LazyAd** aims to turn a product prompt or description into a finished, high-impact product advertisement MP4 automatically:
**Product description / prompt → product visual generation → 3D reconstruction → automated cinematic camera & scene rendering → script generation → voiceover → composited MP4 ad.**

### Core Development Workflow
- **No local CLI, no worker state machines, no heartbeat systems, and no React web app** in the MVP.
- Development is strictly **Notebook-First**: Antigravity generates code for execution in **Google Colab**.
- Colab is the primary compute and runtime environment (GPU + CPU).
- The user will **never manually operate Blender or build 3D scenes by hand**. All camera movements, lighting, and frame rendering must be completely programmatic.
- Initial product categories planned: **watches, cars, and motorcycles**. The MVP strictly narrows focus to **one fictional luxury watch**.

### Staged Implementation Strategy
- **Do not assemble a monolithic notebook on Day 1.** Putting image generation, 3D reconstruction, headless rendering, audio synthesis, and composition into a single notebook immediately makes debugging and memory isolation painful.
- Phase 1 executes as **five discrete, self-contained validation spikes (S1 to S5)**. Each spike tests one isolated capability with explicit pass/fail criteria.
- **None of the spikes are assumed to be passed yet.** They represent live engineering experiments that must be executed and recorded sequentially in Colab.
- Only after S1 through S5 pass individually will Antigravity assemble the unified end-to-end notebook (`LazyAd_MVP.ipynb`).

### Feasibility Bottom Line: Can a Colab Notebook Deliver a Watch Ad?
**Yes, the pipeline is technically feasible within Colab, but requires grounded engineering expectations:**

1. **Single 3D Model Baseline:** To avoid brittle CUDA compilation and complex auto-switching in the first build, the MVP selects **TripoSR** as the baseline candidate (~6 GB VRAM default). However, because Colab runtime environments, base images, and pre-installed dependencies fluctuate over time, **Spike S3 must explicitly test and verify TripoSR's installation and execution in the active Colab environment** rather than treating it as an automatic guarantee. Heavier models like TRELLIS ($\ge$16 GB VRAM) are deferred to later isolated spikes.
2. **Single Hero Image Anchoring:** Independent multi-angle image prompts drift visually (different bezels, dials, cases). The pipeline must anchor on **one hero image → one 3D reconstruction**.
3. **Automated, Blender-Free Rendering:** Colab downloads a portable Linux Blender binary via `wget`; a generated Python script runs in the background (`blender -b -P render_scene.py`) to import the GLB, apply HDRi lighting, run procedural camera paths, and render frames via EEVEE. **Zero manual Blender UI.**
4. **Sequential Memory Management:** Running FLUX.1 [schnell] (12B params) alongside 3D models on a 16 GB T4 GPU requires sequential model loading: load image generator $\rightarrow$ generate hero image $\rightarrow$ unload pipeline, purge GPU cache (`torch.cuda.empty_cache()`, `gc.collect()`) $\rightarrow$ load 3D model. SDXL-Lightning/Turbo serves as a fast, low-VRAM fallback.
5. **Realistic Quality Expectations:** Single-image 3D models produce soft edges on watch hands, blurred dial typography, and deformed/hollow case backs. The automated camera choreography must defensively restrict orbits to the front hemisphere ($\pm 35^\circ$), masking unmodeled geometry.
6. **Conditional ₹0 Framing:** The project targets ₹0 incremental spend by leveraging the user's existing Google AI / Colab subscription compute units, free-tier or template scripts, open-weight models, and open-source binaries. This is **conditional** on available subscription units and free quotas, not an unconditional guarantee of infinite free compute.

## 3. High-Level Notebook Pipeline

When assembled after the validation spikes, the unified notebook executes sequentially with strict memory cleanup between heavy stages:

```
[Cell 1: Setup & Env Bootstrap]
  Installs pinned Python packages, downloads portable Blender binary, system libs
        │
        ▼
[Cell 2: Product Input & Fact Record]
  Accepts user prompt / structured facts (case material, dial color, strap, tone)
        │
        ▼
[Cell 3: Hero Product Image Generation]
  Colab GPU loads FLUX.1 [schnell] (or SDXL fallback) → generates centered hero PNG
  CRITICAL: Unloads image pipeline & purges CUDA memory (torch.cuda.empty_cache())
        │
        ▼
[Cell 4: Single-Image 3D Reconstruction]
  Colab GPU loads TripoSR baseline model → generates textured product.glb
  CRITICAL: Unloads 3D model & purges CUDA memory
        │
        ▼
[Cell 5: Automated Mesh Normalization]
  Python script centers mesh, computes bounding sphere, aligns orientation
        │
        ▼
[Cell 6: Grounded Script & Voiceover Generation]
  Populates fact-grounded template script → Kokoro-82M generates VO WAV
        │
        ▼
[Cell 7: Automated Camera & Headless Blender Rendering]
  Headless Blender script executes procedural camera trajectory (reveal, orbit, dial close-up)
  Outputs frame sequence (/content/frames/*.png) via EEVEE
        │
        ▼
[Cell 8: Final Video & Audio Composition]
  FFmpeg muxes video frames + VO + ducked ambient audio + subtitle overlay → ad.mp4
        │
        ▼
[Cell 9: Inline Preview & Optional Drive Save]
  IPython.display.Video preview in Colab + optional Google Drive export
```

## 4. Pipeline Stage Feasibility & Candidate Evaluations

### 4.1 Stage 1: Hero Image Generation

#### The Technical Challenge
Generating multi-angle views directly from text causes severe visual identity drift: bezel markers shift, subdials appear/disappear, and case shapes change. Therefore, **a single high-quality hero image must anchor the entire visual identity.**

#### Candidate Evaluation & Memory Strategy

| Candidate | Colab Fit & Memory Footprint | Speed Goal | Quality & Identity | Licensing | Verdict |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **FLUX.1 [schnell]** | ~12B parameters. Requires FP8 precision or `enable_model_cpu_offload()` on a 16 GB T4. Consumes ~10–12 GB VRAM and significant system RAM. **[VERIFIED]** [R12] | 1–4 steps (benchmark goal: ~15–45s depending on GPU). | Outstanding photorealism, sharp studio lighting, clean cyclorama backgrounds. | **Apache-2.0** (commercial and personal use permitted). **[VERIFIED]** [R12] | **Primary Candidate for Colab.** Must be paired with an immediate memory purge upon completion. |
| **SDXL-Lightning / SDXL-Turbo** | Compact footprint (~6–8 GB VRAM). Fits comfortably on any T4 GPU without CPU offload overhead. **[VERIFIED]** | Extremely fast (1–4 steps, <10s on T4). | Good, but dial typography and watch hands can exhibit slight geometric softness. | Open RAIL++ / Stability Community terms. | **Designated Lightweight Fallback.** Activated automatically if FLUX encounters OOM or excessive paging latency on T4. |
| **Gemini API (Image Generation)** | Zero Colab VRAM (REST API). | 2–5s per call. | High photorealism. | Commercial terms; **free-tier status unresolved/conflicted** in developer forums. [R14][R15] | **Not Recommended for MVP.** Risk of unexpected quota limits or billing requirements. |

#### Memory Management Protocol
1. Query available GPU VRAM before loading.
2. If assigned an A100 ($\ge$40 GB), load FLUX.1 [schnell] in bfloat16.
3. If assigned a T4 (15 GB), load FLUX.1 [schnell] with `enable_model_cpu_offload()` and FP8 transformer weights.
4. If FLUX raises an `OutOfMemoryError`, fall back cleanly to `SDXL-Lightning`.
5. **Immediately after image generation:**
   ```python
   del pipe
   gc.collect()
   torch.cuda.empty_cache()
   ```

#### Hero Image Prompting Strategy
Use a strict, unembellished studio prompt template:
`"Professional commercial studio product photography of a fictional luxury [material] watch with [color] dial, [strap type], centered, 45-degree three-quarter isometric view, plain neutral light-grey cyclorama background, soft studio softbox lighting, high detail, 8k, no text, no logo"`

### 4.2 Stage 2: Single-Image 3D Reconstruction

#### The Technical Challenge
Reconstructing a 3D watch from a single 2D image requires inferring depth, thickness, and the unseen back of the watch.
- Watches have hard-surface metallic edges, circular bezels, transparent sapphire glass, and intricate bracelets.
- AI feed-forward models naturally excel at convex organic shapes, but hard-surface geometric symmetry and sharp edges are challenging.
- **The back of the watch will be melted/hallucinated.** This is acceptable *only if* the automated camera is restricted to the front hemisphere.

#### Model Comparison & Practical Selection

| Model | Architecture & VRAM | Installation Complexity | Output Quality & Mesh | License | MVP Selection |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **TripoSR** | Feed-forward transformer. **~6 GB VRAM default.** Fits easily on free T4 and premium Colab runtimes. **[VERIFIED]** [R1] | **Moderate/Empirical:** Standard PyTorch and `trimesh`. Setup is lightweight, but **Spike S3 must verify compatibility against Colab's active pre-installed CUDA/PyTorch packages**. | Solid geometry, vertex-colored/diffuse texture. Lacks PBR specular maps, but geometry is watertight and predictable. | **MIT** **[VERIFIED]** [R1] | **Selected Baseline Candidate for MVP.** Lowest installation friction and VRAM footprint; must be validated in S3 before assembling the full pipeline. |
| **TRELLIS (v1)** | Sparse 3D VAE / Latent Flow. **Requires $\ge$16 GB VRAM.** Tested on A100/A6000 hardware. **[VERIFIED]** [R8] | **High:** Requires compiling custom C++/CUDA kernels (`curope`, `diff-gaussian-rasterization`, `nvdiffrast`). Setup takes 5–10 mins and is prone to CUDA mismatch errors. | Sharper geometry and texture detail than TripoSR. | **MIT** **[VERIFIED]** [R8] | **Deferred to Phase 2 Spike.** Too heavy and brittle for the first MVP baseline. |
| **TRELLIS.2-4B** | 4B-parameter model. **Requires $\ge$24 GB VRAM.** **[VERIFIED]** [R9] | **Very High:** Heavy dependencies, large weight downloads. | Native PBR materials (normal, roughness, metallic). | **MIT** **[VERIFIED]** [R9] | **Deferred to Phase 2.** Requires dedicated A100/A6000 hardware; impractical for initial baseline. |
| **Stable Fast 3D (SF3D)** | TripoSR derivative with UV unwrapping. ~8–10 GB VRAM. **[VERIFIED]** [R2] | Moderate: Gated Hugging Face repository; requires user HF token and license agreement. **[VERIFIED]** [R2] | Fast (0.5s) **[VENDOR CLAIM]**. UV unwrapped textures, reduced baked lighting. | Stability Community License: Free up to \$1M annual revenue. **[VERIFIED]** [R2] | **Potential Upgrade Candidate.** Good texture layout, but gated access adds friction to an automated notebook. |

#### Stage 2 Decision
- **Select TripoSR as the single 3D baseline candidate for the Phase 1 MVP.**
- Do not implement automatic fallback or runtime CUDA compilation between TRELLIS and TripoSR in the first build.
- **Spike S3 must empirically verify that TripoSR installs and generates a valid GLB in the active Colab runtime.** Once this baseline pipeline is proven end-to-end, heavier models like TRELLIS can be benchmarked in a dedicated upgrade spike.

### 4.3 Stage 3: Programmatic 3D Scene Setup & Automated Camera Rendering

#### The Constraint
The user will **not** open Blender, build 3D scenes by hand, or manipulate keyframes manually. All camera orbits, lighting, and frame captures must execute **programmatically within the Colab environment**.

#### Headless Blender Execution Pattern (`blender-python`)
Colab downloads a standalone portable Linux Blender binary (`tar.xz`) via `wget`. A generated Python script runs in the background:
```bash
!blender -b -P render_scene.py -- --mesh /content/product.glb --out /content/frames/
```

**Why this approach is superior in Colab:**
1. **Zero UI:** The user never opens or interacts with Blender.
2. **Photorealistic EEVEE Engine:** Provides real metallic specular highlights, contact shadows, anisotropic reflections, and depth of field.
3. **No Virtual Display Needed:** Headless Blender (`blender -b`) runs natively in Linux terminal environments without requiring X11, Xvfb, or unstable headless Chromium WebGL flags.

#### Automated Cinematic Camera Choreography (Defensive Design)
To completely conceal the unmodeled/hallucinated back of the single-image 3D mesh, the camera script programs four sequential shots (total 6–8 seconds / 180–240 frames @ 30fps):

```
Shot 1 (0.0s – 2.0s): Reveal / Dolly-In
  Camera begins slightly elevated, wide focal length, dollying in toward the watch face.
  Depth of field shifts smoothly from soft focus to crisp focus on the dial.

Shot 2 (2.0s – 4.5s): Controlled Front-Hemisphere Orbit
  Camera sweeps in a conservative arc of ±35° across the front of the watch.
  Key light sweeps across the dial, catching reflections along the bezel and case chamfer.

Shot 3 (4.5s – 6.5s): Macro Detail Pan
  Close-up macro lens panning from the winding crown across the dial markers.

Shot 4 (6.5s – 8.0s): Hero Standoff & Logo Hold
  Camera pulls back to a stable three-quarter hero pose.
  Subtle floating drift while tagline / call-to-action text appears.
```

### 4.4 Stage 4: Script Generation and Fact Grounding

#### Realistic Factual Strategy: Template-First
Deterministic rule-based regex checks cannot reliably catch all implied or subtle claims in free-form LLM output. To guarantee absolute factual safety without complexity:

1. **Primary MVP Default: Deterministic Template Script**
   Populate pre-formatted luxury advertising copy directly from the supplied product facts:
   `"Crafted in [case_material]. Defined by [dial_color]. The [product_name] represents precision refined."`
   - 100% factually grounded by definition.
   - Requires zero API calls, zero cost, and zero network dependency.
   - Guaranteed word count (18–22 words), perfectly calibrated for a 6–8 second voiceover.

2. **Secondary Enhancement (Optional LLM Generation):**
   - Provide an optional cell using the free Gemini API (`gemini-1.5-flash` or `gemini-2.0-flash`) with strict negative prompting.
   - If the API call fails or exceeds quota, the notebook defaults instantly to the template script.

### 4.5 Stage 5: Voiceover Generation (TTS)

#### Candidate Selection: Kokoro-82M
- **Footprint:** 82M parameters (~350 MB download).
- **Execution:** Runs locally in Colab on CPU or GPU in <1.5 seconds.
- **Quality:** Exceptionally natural, expressive delivery with British and American voice profiles (e.g. `af_heart`, `am_adam`, `bf_emma`). **[SECONDARY]** [R24]
- **Licensing:** **Apache-2.0** weights. **[VERIFIED]** [R23]
- **Cost:** 100% free; requires no API keys, accounts, or character tokens.

The notebook synthesizes `voiceover.wav`, measures its exact duration using `soundfile`, and passes that duration to the video timeline calculation.

### 4.6 Stage 6: Video & Audio Composition (FFmpeg)

Google Colab runtimes include FFmpeg pre-installed (`/usr/bin/ffmpeg`). FFmpeg executes the final assembly in a single command:
1. Assembles rendered PNG frames (`/content/frames/%04d.png`) at 30 fps.
2. Synchronizes `voiceover.wav`.
3. Mixes a royalty-free ambient audio loop, ducked by -14dB beneath the voiceover using FFmpeg's `sidechaincompress` filter.
4. Applies a subtle text overlay with the product name and tagline.
5. Encodes to H.264 video (`libx264`, `yuv420p`) and AAC audio in an MP4 container, ready for immediate playback via `IPython.display.Video`.

## 6. Major Technical Risks & Realistic Quality Limitations

| # | Limitation / Risk | Root Cause | Visible Impact | Realistic Defense / Mitigation |
| :- | :--- | :--- | :--- | :--- |
| **1** | **Dial text & micro-logos are distorted.** | Diffusion models and single-image 3D reconstructors cannot render legible typography on tiny watch faces. | Watch dial exhibits geometric markers and hands, but brand lettering appears blurred or abstract. | **Embrace minimalist dial styling.** Prompt for "clean minimalist dial with geometric hour batons and no brand text". Use FFmpeg text overlays for readable branding. |
| **2** | **Watch hands lack razor-sharp hard edges.** | Neural marching cubes in single-image models round off thin geometries. | Hands may look slightly embossed rather than floating mechanisms. | Use cinematic depth-of-field (shallow focus) and continuous camera motion to prevent static inspection of fine geometry. |
| **3** | **Case back is deformed or hollow.** | Single-image reconstruction models cannot see the rear of the watch; they hallucinate a rough convex blob. | Showing the rear ruins the commercial illusion immediately. | **Strict front-hemisphere camera constraint:** The camera script is hard-coded to never orbit past $\pm 35^\circ$ from the hero angle. |
| **4** | **Baked reflections on metal case.** | 2D images have studio lighting baked into diffuse textures. | Reflections do not shift naturally across polished metal during camera pans. | In the Blender script, combine an HDRi environment map with diffused area lights, and assign a subtle metallic/roughness material override. |
| **5** | **GPU OOM on T4 instances.** | Holding large models in GPU memory simultaneously triggers out-of-memory crashes. | Notebook crashes during stage transitions. | **Sequential memory purge:** Delete pipelines and call `torch.cuda.empty_cache()` between image generation, 3D reconstruction, and rendering. |

## 8. Staged Phase 1 Implementation Plan (Sequential Validation Spikes)

To avoid debugging a complex monolithic notebook, Phase 1 is strictly structured as **five sequential, independent proof-of-concept spikes**. 

> **Important Validation Rule:** None of the spikes below are assumed to have passed. Each spike is an empirical test designed to validate an unverified assumption in the active Colab environment. Each stage must pass its documented criteria before Antigravity writes the next spike:

```
[Spike S1: Colab Diagnostic & Hardware Profiling]
       │ (Must verify GPU & compute environment)
       ▼
[Spike S2: Hero Image Generation & Memory Purge]
       │ (Must verify FLUX/SDXL memory cleanup)
       ▼
[Spike S3: Baseline 3D Reconstruction (TripoSR)]
       │ (Must empirically verify TripoSR install & GLB output)
       ▼
[Spike S4: Headless Blender Programmatic Render]
       │ (Must verify automated EEVEE scene & camera orbit)
       ▼
[Spike S5: Audio Synthesis & Final Composition]
       │ (Must verify Kokoro TTS & FFmpeg muxing)
       ▼
[Assembly of Unified End-to-End Notebook: LazyAd_MVP.ipynb]
```

### Spike S1: Colab Diagnostic & Hardware Profiling
- **Objective:** Query the assigned Colab runtime to identify GPU model, total VRAM, CUDA version, system RAM, and disk space.
- **Pass Criteria:** Diagnostic script executes cleanly, logs hardware specs, and confirms GPU availability.

### Spike S2: Hero Image Generation & Memory Cleanup
- **Objective:** Test FLUX.1 [schnell] in Colab with memory offloading. Generate one clean luxury watch hero image on a plain background. Test memory purge (`del pipe`, `torch.cuda.empty_cache()`). Verify SDXL-Lightning fallback if VRAM is insufficient.
- **Pass Criteria:** Generates a usable, centered watch image in under 60 seconds; GPU memory is successfully freed for the next stage.

### Spike S3: Baseline 3D Reconstruction (TripoSR)
- **Objective:** Empirically install TripoSR in the active Colab environment, feed the exact hero image from S2, and generate `product.glb`. Inspect mesh integrity, triangle count, and texture application.
- **Pass Criteria:** Successfully builds and installs without dependency conflicts, and exports a valid, watertight GLB file without out-of-memory errors.

### Spike S4: Headless Blender Programmatic Render
- **Objective:** Download portable Linux Blender archive, run headless script (`blender -b -P render_test.py`), load `product.glb`, add studio lighting, and render a short (60-frame) test orbit.
- **Pass Criteria:** Renders 60 frames to `/content/frames/*.png` without opening a GUI; metallic highlights and dial are visibly rendered with zero manual keyframing.

### Spike S5: Audio Synthesis & Final Composition
- **Objective:** Run Kokoro-82M TTS on the template script to generate `voiceover.wav`. Use FFmpeg to combine the S4 frame sequence, voiceover, and an ambient audio loop into a finished MP4.
- **Pass Criteria:** Produces a playable MP4 file in `/content/output/` that renders inline via `IPython.display.Video`.
